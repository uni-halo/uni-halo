# PRD：APP 端内容发布与恋爱模块管理

> 版本：v0.1 草案 ｜ 状态：待评审 ｜ 日期：2026-09-16

## 1. 背景与目标

uni-halo 客户端目前已具备完整登录体系（账号密码 + 微信，插件端签发 token，含 roles/permissions），业务页面以「只读消费」为主。本需求为 APP 端补齐**内容生产与管理能力**：

1. APP 端发布瞬间（图文，含图片上传）
2. APP 端管理恋爱模块内容：恋爱清单、恋爱相册、恋爱故事（增删改，含图片上传）

## 2. 可行性结论（已核实）

| 依赖项 | 结论 | 依据 |
|--------|------|------|
| 客户端认证链路 | ✅ 就绪 | `store/token.ts` + `http/alova.ts`（`meta.needAuthToken` 自动携带 `Authorization: Bearer`）；`uploadFile` 拦截器同样带 token |
| 图片上传（Halo 官方） | ✅ 官方支持 | `POST /apis/api.console.halo.run/v1alpha1/attachments/upload`，multipart（`file` / `policyName` / `groupName`），返回 `Attachment`（`status.permalink` 为最终 URL） |
| 发布瞬间（Halo 官方） | ✅ 官方支持 | 瞬间插件 UC API：`POST /apis/uc.api.moment.halo.run/v1alpha1/moments`（自助发布；无审核权限时 `approved=false` 待审）。管理员走 Console API `console.api.moment.halo.run/v1alpha1/moments` |
| 恋爱模块 CRUD | ⚠️ 待确认 | 客户端仅有公开读接口（love-albums / love-daily-items / love-stories）。**需插件端提供 create/update/delete 接口**，为唯一外部依赖 |
| APP 端登录方式 | ✅ 可用 | APP 无法用微信 code 登录，走账号密码 `loginByPassword`（已实现） |

## 3. 用户与角色

| 角色 | 能力 |
|------|------|
| 普通登录用户（reader） | 无发布/管理入口 |
| 作者（author）及以上 | 发布瞬间（UC 接口，可能需审核）；恋爱模块管理（以插件端权限为准） |
| 管理员（admin） | 直发瞬间（免审）；恋爱模块全部管理能力；删除他人内容 |

权限控制原则：**客户端只做入口显隐（依据 `userInfo.roles`），鉴权以插件端/Halo 为准**。

## 4. 功能需求

### 4.1 F1 发布瞬间（APP）

- 入口：「瞬间」页右上角发布按钮（仅 `author`/`admin` 可见；`#ifdef APP-PLUS`，后续可放开到 H5）
- 表单：文本（多行，≤5000 字符）+ 图片（≤9 张，jpg/png/webp，单张 ≤10MB）+ 标签（可选，多个）
- 流程：
  1. 选图 → 立即/提交时上传至 Halo 附件 → 拿 `permalink` 列表
  2. 提交 `POST uc.api.moment.halo.run/v1alpha1/moments`，content 中以 markdown 图片语法携带图片 URL，medium 类型选 `PHOTO`/`TEXT`
  3. 返回 `approved=false` 时提示「已提交，待审核」；成功后返回瞬间列表并刷新
- 异常：上传失败可重试（单图粒度）；提交失败保留草稿（本地暂存，后续版本做草稿箱）

### 4.2 F2 恋爱清单管理（APP）

- 入口：恋爱清单页，作者角色显示「管理」按钮
- 功能：新增条目（标题、描述、封面图、完成状态）、编辑、删除、标记完成
- 接口：**依赖插件端** CRUD（预期 `POST/PUT/DELETE /apis/api.unihalo.ialley.cn/v1alpha1/plugins/uni-halo/love-daily-items[/{name}]`，命名以插件端为准）

### 4.3 F3 恋爱相册管理（APP）

- 入口：相册页管理入口（同角色规则）
- 功能：新建相册（名称、描述）、上传照片（多选，批量上传至 Halo 附件后关联相册）、删除照片、删除相册
- 接口：**依赖插件端** CRUD + 照片关联接口

### 4.4 F4 恋爱故事管理（APP）

- 入口：故事页管理入口（同角色规则）
- 功能：新增故事（标题、正文 markdown、封面图）、编辑、删除
- 接口：**依赖插件端** CRUD

### 4.5 F5 图片上传能力（公共）

- 端点采用 **Halo「附件设置 → 个人中心附件配置」** 对应的 UC 附件 API：
  - `POST /apis/uc.api.storage.halo.run/v1alpha1/attachments/-/upload`
  - multipart 仅需 `file` 字段（name=file），存储策略由站点后台「个人中心附件配置」自动决定，**客户端无需传 policyName/groupName**，author 角色天然有权限
  - 返回 `Attachment`，取 `status.permalink`；若 permalink 未及时生成（部分云存储策略异步），按 `metadata.name` 轮询一次兜底
  - 备选（管理员场景）：Console 端点 `POST /apis/api.console.halo.run/v1alpha1/attachments/upload`（需传 `policyName`），本次不默认使用
- 新增 `useHaloUpload` hook（放 `src/hooks/`，auto-import）：
  - 认证：经现有 `uploadFile` 拦截器自动携带 Bearer token
  - 能力：多图队列串行上传、进度回调、单图失败重试、大小/类型前置校验
- 废弃 `hooks/useUpload.ts` 中写死的 `/upload` demo 端点（保留文件，本次不删）
- 选择图片 API：APP/H5 用 `uni.chooseImage`；后续小程序端接入时条件编译为 `uni.chooseMedia`

## 5. API 层规划

- 管理模块 API 定义**统一放 `src/api/uni-admin.ts`**（alova），类型加在 `src/api/types/uni-admin.ts`
- 全部写接口 `meta: { requestFrom: RequestFrom.Halo, needAuthToken: true }`
- 预期接口清单：

| 函数 | 方法与路径 | 说明 |
|------|-----------|------|
| `uploadAttachment` | POST `/apis/uc.api.storage.halo.run/v1alpha1/attachments/-/upload` | multipart，uni.uploadFile 直传（不走 alova） |
| `createMoment` | POST `/apis/uc.api.moment.halo.run/v1alpha1/moments` | 发布瞬间（UC） |
| `updateMoment` | PUT `/apis/uc.api.moment.halo.run/v1alpha1/moments/{name}` | 编辑自己的瞬间 |
| `deleteMoment` | DELETE `/apis/uc.api.moment.halo.run/v1alpha1/moments/{name}` | 删除自己的瞬间 |
| `createLoveDailyItem` 等 | 插件端 love-daily-items CRUD | ⚠️ 待插件端确认 |
| `createLoveAlbum` / 上传照片关联 等 | 插件端 love-albums CRUD | ⚠️ 待插件端确认 |
| `createLoveStory` 等 | 插件端 love-stories CRUD | ⚠️ 待插件端确认 |

## 6. 非功能需求

- 页面统一放 **`pages-admin` 分包**（`vite.config.ts` 的 `UniPages({ subPackages })` 注册），命名如 `pages-admin/moment-publish/index.vue`、`pages-admin/love/…`
- 请求一律 alova，写接口 `meta: { requestFrom: RequestFrom.Halo, needAuthToken: true }`；类型加 `src/api/types/uni-halo.ts`
- UI 遵循项目规范：UnoCSS 原子类优先、玻璃拟态风格、`wot-ui` 组件
- 上传大图前端不做压缩（APP 端可后续加 `uni.compressImage`），但需 loading/进度反馈
- 合入门禁：`pnpm type-check && pnpm lint && pnpm test:run` 全过

## 9. APP 端 UI 设计（ASCII 示意）

**导航栏约束**：小程序右上角有胶囊按钮，**所有页面导航栏右上角不放任何操作按钮**。主操作一律采用：
- 浏览/列表页 → **右下角悬浮 FAB 球**（类似文章详情悬浮点赞/评论/收藏的交互习惯），仅 author/admin 可见
- 管理/编辑页 → **底部固定主按钮**（安全区适配）
- 统一风格：玻璃拟态卡片、圆角、主题色；导航栏仅返回箭头 + 标题
